# 实现与维护边界

## 数据流

浏览器通过 HTTPS 发请求、WSS 接收事件。每台主机有独立 ID、SQLite、设备授权和 Codex app-server 子进程。浏览器只连接当前所选主机；离开页面不改变进程生命周期。

远程部署由 Cloudflare Tunnel 提供公网 HTTPS 和 WSS，Ubuntu 上的 `cloudflared` 通过出站连接把请求转发到 Pocket 的本机回环地址。Pocket 仍校验公网域名和请求来源，设备授权由当前主机签发。每台主机配置独立隧道和子域名。 [部署步骤](../README.md#安卓手机连接主机)

`packages/codex-transport/vendor` 保留 T3 固定提交 `983654b3b2f7267a69e3d5d049d781aadbbc3166` 的 10 个源码文件，未修改。`UPSTREAM.json` 记录各文件 SHA-256，`verify:vendor` 检测漂移。Effect 4.1.3 与 Node 平台层 4.1.2 按该上游版本锁定。

我们使用该包的原始协议传输层及子进程适配工具，负责 JSONL framing、请求匹配、双向请求、错误传播、进程结束和作用域清理。应用自己的适配层处理消息负载，避免上游生成 schema 对版本漂移的事件静默丢弃。没有复制完整 T3 编排器，也没有重写 JSON-RPC 传输。

独立执行与历史读取使用官方 `codex app-server --listen stdio://`。已有桌面聊天新增 `DesktopBridge` 通道，连接桌面 Unix socket，由原桌面 owner 执行操作。两者不能互换；关闭服务仅关闭自己的子进程与 IPC 连接。

## 身份与持久化

应用聊天 ID 与 Codex 原生线程 ID 分开保存。原生空线程在首次执行前可能尚无 rollout，服务重启后可为从未发送过任务的空聊天重建原生线程。已有或结果不确定的历史不得走此回退。

SQLite 保存聊天、消息条目、待处理请求、事件序号、发送队列、操作回执和授权哈希。事件和对应状态更新在同一事务中提交，然后发布给浏览器。流式文本按 80ms 合并，最终条目立即写入；意外崩溃时最后尚未写入的片段可能丢失，原生历史通过 Codex 保留。

HTTP 读取得到快照游标。浏览器合并实时事件时防止较旧的历史响应覆盖新事件。事件日志保留约 2000 条，游标过期则重新加载快照和当前聊天最近条目。更早消息分页读取。

主机服务重启后，之前活跃的任务显示中断，待处理的原生审批失效，排队消息取消并需用户确认后重新发送。不会自动重放可能已执行的消息。Pocket 自建会话在下一次用户发送时通过 `thread/resume` 恢复；从本机发现的会话重启后回到只读历史，必须显式恢复。

## 执行与控制

每条操作带唯一 ID 和输入指纹。重复 ID 返回已有完成结果；同一个 ID 用于不同内容会被拒绝。跨进程崩溃无法保证本地回执与 Codex 外部效果的原子性，结果不确定时标记待确认，不做“恰好执行一次”的过度承诺。

消息显式区分 queue、steer 和浏览器草稿。queue 持久化并按目录串行；steer 使用 `expectedTurnId` 校验当前轮次后调用 `turn/steer`，失败不转换为队列；草稿不调用主机消息接口。Pocket 自建任务按规范化目录串行，不同目录可以并行。桌面同步仅按已连接聊天状态避让，无法限制用户直接在桌面或未连接聊天中启动并行任务。停止清除该聊天未执行的队列，向其原生线程和轮次发出 `turn/interrupt`，收到结束通知后才显示已中断。停止轮次不承诺终止已脱离生命周期的所有后台进程。

审批通过原生双向请求回调等待，带应用请求 ID、原生请求 ID、聊天与轮次。竞争审批在主机同步领取，只接受一次有效决定。首版支持命令、文件修改、权限请求，以及阻塞式用户问题。未识别的原生请求明确失败，不自动同意。

## 整理、额度与离线草稿

目录收藏存入当前主机 meta，新增收藏仍解析真实路径并校验项目根目录；失效目录允许移除。聊天名称与 pinned 字段保存在聊天 JSON，旧数据库无需破坏性迁移。队列、收藏和额度各自发布事件，快照也包含当前状态，重连无须重放操作。

浏览器草稿以 hostId + chatId 为键存储，切换聊天时独立挂载输入组件，避免草稿串到另一聊天。发请求前先保存“结果待确认”标记，收到成功回执才清空。断线时仅保存未发送内容，恢复后必须点击确认发送；结果不确定时另需勾选已核对记录。离线时不建立自动重试的发送任务。

额度仅白名单提取账号类型、套餐、额度桶、窗口百分比及 Unix 秒重置时间，不转发账号 email 或凭据。额度读取失败不影响聊天服务启动；已显示的旧数据带更新时间与失败提示。账号切换通知清除旧额度，额度推送按 limitId 合并。

浏览器语音适配独立于主机协议，识别结果只进入当前聊天草稿；切换聊天或发送时结束识别。未在此阶段增加转写服务、API Key 或模型部署依赖。

## 访问与多主机

主机通过本地 `auth.json` 配置固定密码，文件仅包含版本、算法、随机盐和 scrypt 哈希（N=32768、r=8、p=1、64 字节输出）。CLI 隐藏输入并原子写入权限 600 的文件；启动时校验格式、权限和普通文件类型。主机密码不通过公开接口返回。

`/api/login` 校验密码后签发高熵独立设备 Cookie，服务端只保存会话哈希。记住设备为 30 天，不勾选为浏览器会话 Cookie 且服务端最长 12 小时；均不滑动续期。登录尝试使用 SQLite 主机级 10 次 / 10 分钟限制，并发校验最多 2 个。密码指纹改变时，在启动事务中清除全部旧会话和配对码；已经设置密码的主机若配置丢失则拒绝启动。

未设置密码的旧版主机保留一次性配对兼容；启用密码后 CLI 和 HTTP 配对入口均拒绝使用。设备授权可查看到期时间并撤销；每个主机使用独立的 Cookie 名，避免同一域名不同端口下相互覆盖。HTTP 有来源、Host 和客户端标识检查；WebSocket 同时验证 Origin 与会话，撤销会话会关闭活动 socket。

每个主机网页保持同源。切换主机通过导航完成，而不是让网页跨域携带另一台机器的凭据。主机名称和地址可通过 fragment 转交给目标网页，再写入目标来源的本地存储并移除 fragment。这不提供账号云同步或聊天迁移。

## 本机已有聊天

`LocalChats` 通过 `thread/list` 分页发现已有聊天，按原生 ID 去重。应用 ID 为 `codex:<nativeId>`，保留来源、控制权和自定义名称；发现、打开、刷新均不调用 `thread/resume`。聊天目录在允许范围外时仍可显示历史，继续执行时重新解析真实路径并校验 `POCKET_ROOTS`。

历史使用 `thread/turns/list(itemsView=full, sortDirection=desc)`，每页 10 轮；旧服务器明确不支持该方法时才回退 `thread/read(includeTurns=true)`。转换消息、命令、变更和摘要，使用聊天 + 轮次 + item ID 防止旧历史的重复数字 ID 冲突。短缓存合并同时到达的读取；发送回执对应的用户消息与原生历史按轮次和正文一对一合并。历史不生成待审批请求、不推断外部进程的运行状态。

继续操作检查工作目录和原生元数据，通过 `thread/resume(excludeTurns=true)` 使用原 ID 恢复；成功后才标记 `control=pocket`。占用错误返回 409；原进程不被终止，不创建替代线程。释放时先拒绝活跃任务/排队消息，调用 `thread/unsubscribe`，再确认 `thread/loaded/list` 不再包含目标。Pocket 启动自己的 app-server 时设置 `thread_unload_delay_secs=0`，仅改变该子进程的无订阅卸载等待，不修改用户 Codex 配置文件。

本机 Codex 0.167.0-alpha.3.2 的双进程实测：第二进程可以读取持久化内容，但对第一进程的运行任务调用 steer/interrupt 返回 thread not found，resume 返回 active writer。第二进程读到的历史甚至可能把原端尚未完成的轮次呈现为 interrupted，因此不能将历史状态作为实时任务状态。这说明独立 app-server 不能控制另一进程。新增的桌面 IPC 桥接绕开了这个架构限制：请求交给原桌面 owner，不以第二个 app-server 恢复 writer。


## 桌面 IPC 桥接

`DesktopIpc` 实现当前用户 Unix socket 上的 4 字节小端长度 + JSON 帧，限制 32 MiB，匹配 requestId 并为每个请求设置超时。`DesktopBridge` 用 owner discovery 确认目标，通过 following 广播订阅版本 11 的完整快照和 revision patches；只接受选定 owner、local host、指定聊天的事件。序号缺口触发只读快照修复，未知协议禁用控制。恢复读连接不会自动重发写操作。

`DesktopSessions` 将桌面状态转换为共享 Chat / Entry / PendingRequest，按 60ms 合并持久化，再复用原 HTTP/WSS。完整桌面状态（模型指令等）仅留在主机内存，不原样转发手机。请求 ID 带连接 epoch，双页面审批在 I/O 前领取；桌面已经处理的请求变为 resolved。断开时旧请求过期、队列取消，重新连接需用户操作。源聊天和桌面状态的 cwd 均经根目录检查；不会通过未知方法任意透传 HTTP 请求。

消息通过 start-turn，运行中消息通过 steer-turn；沿用桌面已有权限配置。停止携带 expectedTurnId，并且只在桌面状态流确认结束后显示已结束。追加指令在发送前后核对轮次，但桌面内部 steer 实现可能在极端换轮竞态中自行重定向；这不是跨进程原子 compare-and-swap，不承诺绝对消除该竞态。结果异常标记未确认，不自动降级为新任务。

该通道依据安装版本的接口行为独立实现，没有复制 Electron 打包源码，不修改桌面安装文件。验证基线为 Linux `26.1103.31037`；不是 OpenAI 支持的公共 SDK。T3 复用模块继续负责独立执行和历史读取，不负责桌面 IPC。首次完整快照较大时可能触发帧上限，当前没有大型聊天的分块同步支持。
